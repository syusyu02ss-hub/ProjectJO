# 평온의 방 · 개발 과정

기획과 플레이 피드백을 바탕으로 무엇을 바꿨고, 왜 바꿨는지 정리한 기록입니다. 초기 설계의 모든 요소가 현재 데모에 구현되어 있다는 뜻은 아닙니다.

## 1. 반복에서 탈출로

초기에는 기억을 지우는 ‘정리’를 겪고, 남겨 둔 수첩을 읽으며 같은 장면에 다시 도전하는 구조였습니다. 세 번째 실패에는 완전 정리와 등록 연출이 이어졌습니다.

설계를 구체화하면서 탈출 동기와 시설의 감시 방식에 의문이 생겼습니다. 주변에 직원이 많은 상황에서 참가자가 사라졌는데도 자유롭게 이동하는 전개, 기억이 지워지는 인물끼리 신뢰를 쌓아야 하는 전개가 의도한 긴장감과 맞지 않았습니다.

현재는 잠긴 방에서 깨어난 수혁이 처음부터 탈출을 시도하는 구조입니다. 반복 복귀, 이전 피해자의 일기와 참가 번호 단서는 제거했습니다. 방에서는 사물을 살피고 문을 열 방법을 찾습니다. 불이 꺼지고 문이 열려도 수혁은 그 원인을 알지 못합니다.

후속 이야기의 인물 관계는 [세계관 기준](줄거리-세계관-기준.md)에 따로 정리했습니다. 해당 문서는 스포일러를 포함합니다.

## 2. 기록의 역할 변경

초기 수첩은 주인공이 기억을 잃어도 정보를 이어 주는 이야기 속 소지품이었습니다. 새 구조에서는 긴박한 상황마다 필기를 하는 행동이 자연스럽지 않았습니다.

현재 ‘조사 기록’은 플레이어가 확인한 사실을 다시 보는 참고 화면입니다. 주인공이 직접 쓰는 연출을 요구하지 않습니다. 지나간 대사를 읽는 화면과도 역할이 달라, ESC 메뉴의 두 ‘기록’ 버튼을 ‘조사 기록’과 ‘지난 대사’로 구분했습니다.

## 3. 설명을 줄이고 반응을 남기기

몰입을 높이려고 감각 묘사를 늘렸지만, 모든 행동을 순서대로 서술하면서 문장이 길고 기계적으로 느껴지는 문제가 생겼습니다.

예를 들어 ‘눈꺼풀이 자꾸 내려왔다. 힘을 줘도 다시 감겼다.’는 같은 현상을 반복합니다. 이를 ‘눈꺼풀이 서서히 감긴다.’로 줄이고 짧은 반응을 이어 붙였습니다.

로비의 관계 회상에는 여유를 두고, 방과 복도에서는 그 순간의 감각과 생각을 앞세웠습니다. 시제만 일괄 변경하는 대신 중복 설명을 덜어내는 방향으로 원고를 수정했습니다.

## 4. 화면이 공간을 가리지 않도록

메인 메뉴는 장식과 버튼 배경을 줄이고 명조체 글자 중심으로 정리했습니다. 대화창은 밝은 로비와 어두운 방에서 모두 읽을 수 있도록 검정에 가까운 반투명 패널로 조정했습니다.

인물 표정을 생성할 때 몸과 구도가 미세하게 바뀌어, 대화 중 인물이 움직이는 것처럼 보이는 문제도 겪었습니다. 로비용 이미지의 크기와 여백, 배치 기준을 맞추는 작업을 진행했고, 이후 에셋 제작에서도 공통 기준 원본이 필요하다는 점을 정리했습니다. 생성만으로 픽셀 단위의 일치를 보장할 수 있다고 보지는 않습니다.

개발 중에는 조사 위치 표시가 확인에 도움이 됐지만, 플레이어에게는 탐색의 여지를 줄였습니다. 배포판에서는 표시와 호버 강조를 숨기고 클릭 영역을 유지했습니다. 표시가 없는 탐색이 실제로 얼마나 직관적인지는 테스터 피드백으로 확인할 항목입니다.

## 5. 소리가 멈추는 순간과 선택의 시간

계속 재생되던 틱톡 소리는 집중을 방해한다는 플레이 피드백을 받아 중요한 선택에만 사용하도록 바꿨습니다.

복도에서는 수혁의 걸음과 다른 발소리를 구분했습니다. 수혁이 멈춘 뒤 짧은 정적을 두고, 상대도 멈췄다는 사실을 깨닫게 합니다. 직접 위협을 보여 주기 전의 기다림에 긴장감을 주려는 선택입니다.

문 앞에서는 생각할 시간을 충분히 주고, 복도에서는 7초짜리 감소 바와 0.5초의 유예를 적용했습니다. 이때만 0.32초 간격의 틱톡 소리를 사용합니다. 시간 초과에도 별도의 실패 분기가 있으며, 선택 직전부터 재도전할 수 있습니다.

## 6. 데모로 다듬기

장면 1 완료 안내 대신 문을 나서는 동작에서 복도로 이어지도록 구성했습니다. 데모는 낯선 상대와의 만남에서 끝나며, 이후 이야기는 설계 단계입니다.

Windows 패키지에는 조사 안내를 숨긴 화면과 별도 저장 경로를 적용했습니다. 개발용 테스트·설계 문서·개인 세이브는 배포 대상에서 제외했습니다.

자동화 환경에서는 Ren'Py 실행 전 Windows DLL 오류가 발생해 공식 배포 명령과 런타임 테스트를 완료하지 못했습니다. 초기 데모 ZIP은 설치된 SDK의 Windows 런타임을 포함해 구성하고 압축 무결성을 확인했습니다. 이것은 게임 전체의 실행 검증을 대신하지 않습니다. README의 화면은 제작자가 직접 플레이해 촬영한 자료입니다.

## 다음 피드백에서 확인할 것

- 표시 없이도 조사할 사물을 찾을 수 있는가.
- 복도 선택의 읽기 시간과 긴박감이 적절한가.
- 대사가 반복되거나 감정을 과하게 설명하는 구간이 남아 있는가.
- 음량과 화면 가독성이 다른 PC에서도 적절한가.

기존 설계 문서와 Git 이력은 보존합니다. 이 문서는 외부 테스터의 평가 결과를 주장하는 문서가 아니라, 제작 과정에서 내린 결정과 앞으로 확인할 항목을 정리한 문서입니다.
